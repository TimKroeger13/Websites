=========================================================
 Software-Downloadseite: Dateien auf den Server kopieren
=========================================================

Ziel im Netz:  https://tkroeger.com/websites/Software/
(gleiches Schema wie die anderen Projekte, z.B.
 https://tkroeger.com/websites/ExtractionCalculator/ )

Platzhalter vorher ersetzen:
  BENUTZER   = SSH-Benutzername   (z.B. tim)
  SERVER     = tkroeger.com       (oder die IP des Servers)
  ZIELPFAD   = Ordner auf dem Server, in dem "websites" liegt,
               plus /websites/Software
               (z.B. /var/www/html/websites/Software)


---------------------------------------------------------
1) Neue Datei lokal ablegen
---------------------------------------------------------
Datei hier hineinkopieren:

    G:\Repos\Websites\Software\files\

WICHTIG, seit es die Versionsverwaltung gibt:
Die Versionsnummer gehoert IN DEN DATEINAMEN.

    LolGroupBotAgent-Setup-1.5.0.exe     richtig
    LolGroupBotAgent-Setup.exe           falsch

Grund: jede Version ist eine eigene Datei. Nur dadurch
bleibt die alte erreichbar, wenn die neue klemmt - und nur
dadurch kann der Server die Downloads je Version zaehlen,
denn er zaehlt Dateinamen.

Die alte Datei wird NICHT geloescht. Sie bleibt liegen und
erscheint auf der Seite unter "Alle Versionen anzeigen".


---------------------------------------------------------
2) Dateiliste neu erzeugen
---------------------------------------------------------
In PowerShell im Ordner G:\Repos\Websites\Software :

    powershell -ExecutionPolicy Bypass -File .\make-manifest.ps1

Das schreibt files\files.json (Name, Groesse, Datum, Version).
Die Webseite liest diese Datei - ohne den Schritt taucht
die neue Datei nicht in der Liste auf.

Die Versionsnummer liest das Skript aus der EXE selbst (dort
steht sie im Dateikopf, Inno Setup traegt sie ein). Von Hand
nachtragen muss man sie also nicht - und sie kann auch nicht
veralten, wenn eine neue EXE unter altem Namen dazukommt.

Das Skript fasst Dateien desselben Programms zusammen: alles
vor der Nummer ist der Programmschluessel. Aus

    LolGroupBotAgent-Setup-1.5.0.exe
    LolGroupBotAgent-Setup-1.2.0.exe

wird ein Eintrag mit zwei Versionen, neueste zuerst.

Von Hand in files.json gepflegt, und beim naechsten Lauf des
Skripts erhalten bleiben:

  je Programm   "name"         Anzeigename ("LolGroupBot Agent")
                "description"  Kurzbeschreibung

  je Version    "changes"      was in dieser Version neu ist
                "aliases"      frueherer Dateiname, falls die
                               Datei umbenannt wurde - damit
                               ihre alten Downloads weiter
                               mitgezaehlt werden
                "version"      nur bei Dateien ohne Dateikopf
                               (ZIP, PDF)


---------------------------------------------------------
3a) Hochladen mit scp  (ist in Windows 11 schon dabei)
---------------------------------------------------------
Einzelne Datei:

    scp "G:\Repos\Websites\Software\files\MeinTool.exe" BENUTZER@SERVER:ZIELPFAD/files/

######## HERE
    scp "G:\Repos\Websites\Software\files\LolGroupBotAgent-Setup-1.5.0.exe" jerry@157.230.20.182:/home/jerry/Websites/Software/files/

Kompletter Ordner inkl. index.html (Punkt am Ende beachten):

    scp -r "G:\Repos\Websites\Software\." BENUTZER@SERVER:ZIELPFAD/

Nur die Dateiliste nachschieben:

######## HERE
    scp "G:\Repos\Websites\Software\files\files.json" jerry@157.230.20.182:/home/jerry/Websites/Software/files/


---------------------------------------------------------
3b) Hochladen mit rsync  (schneller, nur Aenderungen)
---------------------------------------------------------
Braucht rsync (z.B. ueber WSL oder Git Bash):

    rsync -avz --delete --exclude "files/downloads.json" \
          "/g/Repos/Websites/Software/" BENUTZER@SERVER:ZIELPFAD/

  -a  Rechte/Zeitstempel behalten
  -v  zeigt was passiert
  -z  komprimiert waehrend der Uebertragung
  --delete  loescht auf dem Server, was lokal weg ist  (VORSICHT)

  --exclude ist wichtig: downloads.json entsteht auf dem Server
  und liegt hier nie vor. Ohne die Zeile wuerde --delete die
  gezaehlten Downloads bei jedem Hochladen wegwerfen.

Testlauf ohne etwas zu veraendern: zusaetzlich --dry-run anhaengen.


---------------------------------------------------------
3c) Hochladen mit WinSCP  (grafisch, zum Klicken)
---------------------------------------------------------
Neues Verbindungsziel -> Protokoll SFTP -> SERVER / BENUTZER.
Links lokal nach G:\Repos\Websites\Software\files
Rechts auf dem Server nach ZIELPFAD/files
Dateien per Drag & Drop hinueberziehen,
danach files.json nicht vergessen.


---------------------------------------------------------
4) Rechte auf dem Server pruefen (einmalig)
---------------------------------------------------------
    ssh BENUTZER@SERVER
    chmod -R 755 ZIELPFAD
    # bei Apache/nginx ggf. Besitzer setzen:
    sudo chown -R www-data:www-data ZIELPFAD


---------------------------------------------------------
5) Git
---------------------------------------------------------
Die .exe-Dateien werden NICHT ins Repo eingecheckt.
Geregelt in G:\Repos\Websites\.gitignore :

    Software/files/*
    !Software/files/.gitkeep
    Software/files/files.json

Es wandert also nur der leere Ordner (mit der Platzhalterdatei
.gitkeep) ins Git - die Programme kommen ausschliesslich per
Upload auf den Server.

Pruefen, was wirklich committet wuerde:

    git -C G:\Repos\Websites status --porcelain -uall


---------------------------------------------------------
5b) Downloadzaehler (einmalig einrichten)
---------------------------------------------------------
Die Seite zeigt hinter jeder Datei "123 Downloads", sobald
files/downloads.json auf dem Server liegt. Fehlt die Datei,
steht dort einfach nichts - die Seite laeuft normal weiter.

Gezaehlt wird aus dem Zugriffsprotokoll des Webservers. Kein
PHP, keine Datenbank, kein zusaetzlicher Dienst: die Seite
bleibt statisch.

Einmalig:

    scp "G:\Repos\Websites\Software\count-downloads.sh" jerry@157.230.20.182:/home/jerry/Websites/Software/
    ssh jerry@157.230.20.182
    chmod +x /home/jerry/Websites/Software/count-downloads.sh
    /home/jerry/Websites/Software/count-downloads.sh

Der letzte Befehl gibt die gezaehlten Dateien aus. Kommt
"Keine Downloads gefunden", stimmen die Pfade oben im Skript
nicht - LOGS (Standard /var/log/nginx) und PFAD (der Teil der
URL vor dem Dateinamen) anpassen.

Danach stuendlich automatisch:

    crontab -e
    17 * * * * /home/jerry/Websites/Software/count-downloads.sh >/dev/null 2>&1

Diesen Schritt WIRKLICH machen und nachsehen, ob er steht:

    crontab -l | grep count-downloads

Ohne ihn bleibt die einmal von Hand erzeugte downloads.json fuer immer
stehen, und auf der Seite steht bei jeder neuen Version "noch keine
Downloads" - genau das ist zwischen Oktober und November 2026 passiert.
Liest der Benutzer die Protokolle in /var/log/nginx nicht (meist gehoeren
sie root:adm), dann stattdessen in die crontab von root:

    sudo crontab -e

Gezaehlt wird jeder vollstaendige Abruf (GET mit Status 200).
Fortgesetzte Uebertragungen (206) und HEAD-Anfragen bleiben
draussen, damit ein Download nicht doppelt zaehlt. Die
rotierten Protokolle (access.log.1, *.gz) werden mitgelesen -
sonst faenge die Zahl jede Woche wieder bei null an.

Und weil logrotate die aeltesten Protokolle irgendwann doch
wegwirft, behaelt das Skript je Datei das Hoehere von alter
und neu gezaehlter Zahl. Ein Download, der einmal passiert
ist, verschwindet dadurch nicht wieder. downloads.json also
nie von Hand loeschen - die Zahl darin ist das Gedaechtnis,
das Protokoll reicht nur zwei Wochen zurueck.

6) Kontrolle
---------------------------------------------------------
Im Browser aufrufen:  https://tkroeger.com/websites/Software/
Neue Datei nicht sichtbar?  ->  Strg+F5 (Cache leeren)
                            ->  liegt files.json wirklich im Ordner files/ ?

Danach am besten noch auf der Profilseite verlinken:
    https://tkroeger.com/index/  ->  Abschnitt "Projects"

Hinweis: index.html per Doppelklick lokal zu oeffnen zeigt oft
keine Liste (Browser blockiert file://). Zum lokalen Testen:

    cd G:\Repos\Websites\Software
    python -m http.server 8000
    Browser:  http://localhost:8000
